# v0.3–v0.5 validation error review

## Scope

This review reads only the saved validation result archives for v0.3, v0.4,
and v0.5. It does not read or evaluate the held-out test split. All results
use the same 48 family-disjoint validation transcripts. Counts below include
invalid outputs as failures; field-level comparisons require schema-valid
outputs, consistent with the evaluator.

## Aggregate diagnosis

| Version | Valid | Correctness exact | Taxonomy exact | Error-taxonomy exact* | First-error exact | All three on eligible errors** |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v0.3 | 47/48 | 34/48 | 23/48 | 6/28 | 14/28 | 3/28 |
| v0.4 | 46/48 | 27/48 | 18/48 | 10/28 | 20/28 | 4/28 |
| v0.5 | 47/48 | 30/48 | 21/48 | 8/28 | 15/28 | 6/28 |

\* Error-taxonomy exact excludes gold `none` and uses valid outputs.

\** A transcript with a gold first-error step for which correctness,
taxonomy, and first-error step are all exact. This is a supplementary joint
diagnostic, not the model-selection metric.

v0.5 is the best balanced recipe: it recovers three correctness decisions
relative to v0.4, retains most of v0.4's taxonomy improvement over v0.3, and
doubles v0.3's complete error-diagnosis count. It still trails v0.3 in pure
correctness and v0.4 in first-error localization. The small validation set and
rare labels mean these comparisons are directional rather than conclusive.

## Where v0.5 fails

### Taxonomy is the main bottleneck

Among valid v0.5 error cases, the recurring missed taxonomy transitions are:

| Gold label | Predicted label | Count |
| --- | --- | ---: |
| algebra | none | 2 |
| algebra | antiderivative | 2 |
| sign | substitution | 2 |
| antiderivative | none | 2 |
| antiderivative | other | 2 |
| antiderivative | algebra | 2 |

The model often recognizes that a solution is wrong without choosing the
right *first* error class, or calls an error-free continuation `none`. These
patterns support focused contrastive examples that isolate one invalid
transformation at a time; they do not support another global oversampling
pass.

### Topic and difficulty clusters

For v0.5, trig integrals are weakest for correctness (2/7) and taxonomy (2/7).
Integration by parts has strong correctness (5/6) but weak first-error
localization (1/4). Partial fractions has strong localization (4/4 eligible)
but weak taxonomy accuracy (1/6). These are distinct failure modes and should
not be treated as a single generic "math" deficit.

Hard examples remain weaker than medium examples: correctness is 15/26 versus
15/22, taxonomy exact is 10/26 versus 11/22, and first-error exact is 6/14
versus 9/14. The sparse taxonomy counts make label-specific rates unstable;
several labels occur only once in validation.

### Recipe tradeoffs

Relative to v0.3, v0.5 gains correctness on two partial-fractions transcripts
but loses six correctness decisions, including trig, trig-substitution,
partial-fractions, improper-integral, and mixed-review examples. Relative to
v0.4, v0.5 gains six correctness and seven taxonomy decisions, while losing
three correctness and four taxonomy decisions. This is consistent with v0.5
moderating, rather than eliminating, the v0.3/v0.4 tradeoff.

Each version produced the same invalid taxonomy-label output for
`int_sub_0035`; v0.4 also produced malformed JSON for `int_trigsub_0107`.
Because v0.5 returns to 47/48 validity, structured output formatting is a
secondary concern compared with semantic classification.

## Decision and next experiment

Do not tune v0.5 further before the controlled cross-family comparison. Freeze
the v0.5 sampling policy, prompt, QLoRA settings, step budget, decoding, and
validation split. Compare other base-model families under that protocol, then
select one final model from validation results before a single held-out test
evaluation.

If the selected cross-family results retain the same algebra/sign/
antiderivative confusions, the next data intervention should be a separately
versioned contrastive, reviewed training expansion: paired correct and
single-first-error transcripts, with explicit taxonomy and step supervision.
Avoid uniform whole-record oversampling, which v0.4 showed can substantially
reduce correctness.

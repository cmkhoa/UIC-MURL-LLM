# v0.1 full QLoRA validation error review

## Scope

This review analyzes the 48 validation predictions from the full v0.1 QLoRA
adapter. It uses the saved adapter-validation artifact only; the held-out test
split was not read.

## Findings

The adapter produced valid schema-conforming JSON for all 48 examples. The
remaining errors are primarily label-selection errors rather than format
failures.

| Pattern | Evidence |
| --- | --- |
| `incorrect` is under-predicted | Of 19 gold `incorrect` examples, 8 were predicted `incorrect` and 10 were predicted `minor_error`. |
| `insufficient_work` is never predicted | Both gold `insufficient_work` examples were assigned another label. |
| `substitution` is over-predicted | The model predicted `substitution` 10 times, compared with 1 gold `substitution` example. |
| First-error localization needs work | 15 of 29 localized errors had the exact first-error step; several misses selected a downstream step or `null`. |
| Trigonometric integrals are the weakest topic | They had 14.3% correctness accuracy on 7 validation examples. |

The review also found that the existing SFT system prompt asks for allowed
labels but does not define them. The failures match this missing instruction:
the model treats material conceptual mistakes as `minor_error`, infers errors
from terse work instead of using `insufficient_work`, and assigns an overly
broad `substitution` taxonomy.

## Chosen v0.2 change

The next run changes only the SFT system prompt. The new
[`v0.2 label-guidance prompt`](../prompts/v0.2-sft-system.md) includes the
benchmark's correctness definitions, taxonomy definitions, and the
first-error rules. The training examples, model revision, QLoRA parameters,
number of steps, seed, and validation split are unchanged.

The prompt is incorporated into a new training-only SFT file,
`data/training/v0.2-sft-train.jsonl` (155 examples; SHA-256
`0754b31ac583b41594f101b789ce87e5d41a15a3c5800853145fa5d570076683`).
Its source remains `data/processed/train.jsonl`; no validation or test
examples were included.

[`configs/qlora-v0.2-label-guidance.yaml`](../configs/qlora-v0.2-label-guidance.yaml)
keeps the v0.1 training settings fixed and specifies a fresh matching base
control and adapter validation run. It is ready to run next.

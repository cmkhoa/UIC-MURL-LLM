# v0.6 hierarchical multi-task SFT plan

## Question

Can staged, field-weighted supervision improve correctness, taxonomy, and
first-error localization together, without changing the frozen v0.5 training
data or reading validation/test examples to construct training data?

## Fixed inputs

Use Qwen2.5-3B-Instruct at the v0.5 pinned revision, the 293-record
`v0.5-sft-train.jsonl`, v0.2 system prompt, seed `20261004`, NF4/FP16 QLoRA
(rank 8, alpha 16, dropout 0.05), total 60 optimizer steps, effective batch
size 8, sequence cap 2048, and v0.5 greedy validation decoding. The only
changed factor is the supervised-loss schedule. The validation and test splits
are not inputs to data generation or tuning.

## Treatment

The final response remains the existing canonical JSON contract. Loss is
computed only on assistant tokens and weighted by field:

1. **Decision phase, steps 1–30.** Weight `overall_correctness` tokens 4×;
   weight `first_error_step` and `error_taxonomy` tokens 1×; all remaining
   assistant tokens 1×.
2. **Diagnosis phase, steps 31–60.** Weight `overall_correctness` 1× and
   `first_error_step` plus `error_taxonomy` 4×; all remaining assistant tokens
   1×.

This is hierarchical because the model first concentrates on the upstream
correctness decision before concentrating on the conditional diagnosis fields.
It is multi-task because all fields remain supervised in both phases. Weights
apply to the complete JSON fields, including their keys and values, so the
model retains the required schema order and grammar.

## Controls and success criteria

Run the matching untouched base control and one v0.6 adapter validation on the
fixed 48-record validation split. Archive source, control, training, adapter
validation, and executed notebook locally and in Drive, verify ZIPs and hashes,
then stop the T4.

Compare v0.6 with v0.3–v0.5. A promising result requires at least 47/48 valid
outputs and simultaneous improvement over v0.5 in the balanced utility
`(correctness accuracy over all 48 + taxonomy macro F1 + first-error exact)/3`.
Report components separately. If it does not meet that prospective criterion,
retain v0.5 for the cross-family comparison. Do not evaluate the held-out test
set.

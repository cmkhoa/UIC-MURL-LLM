# v0.4 taxonomy-balanced SFT validation experiment

## Status

Completed on validation on 2026-10-24. Equal-taxonomy oversampling improves
taxonomy and first-error localization but substantially reduces correctness
relative to v0.2/v0.3. It is not an overall winner, and no final model is
selected for held-out testing.

## Frozen sampling policy

Only `data/processed/train.jsonl` is read by the training-data generator.
The v0.2 system prompt is unchanged. Each of the ten taxonomy labels is
oversampled to the largest training-label count, 68, yielding 680 records
from 155 unique examples. Within each label, seeded shuffled cycles retain
every example before repeating any; a final seeded shuffle mixes labels.
The seed is 20261004. Labels are processed in sorted order. There are no
synthetic examples, target changes, or validation-derived sampling weights.

| Taxonomy | Original | Sampled |
| --- | ---: | ---: |
| none | 68 | 68 |
| antiderivative | 25 | 68 |
| sign | 15 | 68 |
| substitution | 13 | 68 |
| algebra | 13 | 68 |
| other | 7 | 68 |
| bounds | 6 | 68 |
| integration_by_parts | 3 | 68 |
| trig_identity | 3 | 68 |
| partial_fractions | 2 | 68 |

The two partial-fractions examples each appear 34 times. Repetition may
overfit rare labels and reduces exposure to `none`; balancing taxonomy also
changes the correctness-label distribution. This is a sampling intervention,
not additional independent evidence. The fixed 60 steps and effective batch
size of 8 consume 480 records, less than one full balanced dataset pass, so
retention in the file does not guarantee every original example is consumed.

Source, output, prompt, and generator SHA-256 hashes and per-source-ID
multiplicities are recorded in
[`v0.4-sft-train.metadata.json`](../data/training/v0.4-sft-train.metadata.json).
The frozen output SHA-256 is
`275467083d0aec6fb2e7c8e2067ca333465a1bbd212a95be2f38763ceb2da35f`.

## Controlled execution

[`qlora-v0.4-taxonomy-balanced.yaml`](../configs/qlora-v0.4-taxonomy-balanced.yaml)
retains the v0.2 base revision, seed, QLoRA parameters, optimizer settings,
60 steps, validation hash, prompt, and greedy decoding with 256 new tokens.
The matching untouched base control runs under that same prompt on validation.
The source snapshot excludes `data/processed/test.jsonl`. The unchanged
evaluation provenance helper hashes the raw corpus and split manifest; neither
is used to construct training examples or model inference inputs.
The remote runner verifies the validation hash before evaluation.

Reproduce the dataset with:

```bash
python3 scripts/make_sft_dataset.py --system-prompt prompts/v0.2-sft-system.md --balance-taxonomy --seed 20261004 --output data/training/v0.4-sft-train.jsonl --metadata data/training/v0.4-sft-train.metadata.json
python3 -m unittest discover -s evaluation/tests -v
```

All 16 tests passed during preparation. The Colab runner is
[`colab_v04_experiment.py`](../scripts/colab_v04_experiment.py). Mount Drive
first; it sets `HF_HOME=/content/drive/MyDrive/MURL/huggingface-cache` before
loading Hugging Face libraries and persists source, adapter, and verified
archives under `MyDrive/MURL/runs/v0.4-taxonomy-balanced`.

## Validation comparison

| Metric | v0.1 | v0.2 | v0.3 | v0.4 |
| --- | ---: | ---: | ---: | ---: |
| Structured validity | 100.0% | 97.9% | 97.9% | 95.8% (46/48) |
| Correctness accuracy | 58.3% | 66.0% | 72.3% | 58.7% (27/46) |
| Correctness macro F1 | 43.7% | 49.3% | 53.0% | 45.5% |
| Taxonomy macro F1 | 31.7% | 20.7% | 19.7% | 32.7% |
| First-error exact | 51.7% | 53.6% | 50.0% | 71.4% (20/28) |
| First-error mean distance | 0.48 | 0.42 | 0.41 | 0.32 |

Quality metrics use valid outputs only; first-error metrics use the evaluator's
eligible subset. Previous values come from the versioned v0.1–v0.3 reports.
The matching untouched base control produced 0/48 schema-valid outputs. Its
quality metrics are unavailable: evaluator zero values for empty valid-output
subsets must not be interpreted as measured classification performance.

Relative to v0.2, v0.4 gains 12.0 percentage points of taxonomy macro F1 and
17.9 points of first-error exact match, but loses 7.3 points of correctness
accuracy and one valid output. Relative to v0.1, the taxonomy gain is only
about 1.0 point. On gold `none` examples, correctness is 8/17 valid outputs;
v0.3 achieved 16/18. This is consistent with reduced exposure to `none`, but
does not establish causation from one seed on 48 examples. Several rare
taxonomy labels have just one validation example, so their F1 is unstable.

The two invalid adapter outputs were `int_sub_0035` (an unsupported taxonomy
label) and `int_trigsub_0107` (malformed JSON). No outputs were missing or
duplicated.

Counting invalid outputs as unsuccessful, correctness success is 27/48
(56.3%), compared with 28/48 (58.3%), 31/48 (64.6%), and 34/48 (70.8%) for
v0.1, v0.2, and v0.3. This supplementary denominator prevents the lower
validity rate from being hidden by valid-only accuracy.

Training completed all 60 steps (480 sampled records, 0.7059 dataset epochs)
in 793.7 seconds with mean training loss 0.4374. Adapter reload passed.
The GPU was Tesla T4; Torch 2.11.0+cu130 and Transformers 5.20.1 match the
recorded v0.2/v0.3 environments.

weights remain in the persistent Drive cache. Neither fix changed data,
model parameters, sampling, decoding, or metric definitions. The full notebook
retains the setup failures as well as the successful run.

## Next decision

Do not promote v0.4 as the final balanced candidate. Retain it as the strongest
taxonomy/localization candidate and v0.3 as the strongest correctness candidate.
Before selecting one recipe for cross-family runs, test a separately versioned,
train-only moderated balance policy that preserves more `none` exposure; retain
v0.2 guidance and the same fixed-budget controls. Do not launch another
prompt-only experiment or evaluate held-out test.

A [controlled cross-family protocol](v0.4-cross-family-comparison-plan.md) is
prepared, with execution gated on freezing a candidate recipe. It does not
claim that v0.4 has met that gate.

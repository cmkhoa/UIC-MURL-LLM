# v0.7 two-stage diagnosis plan

## Research question

Can the balanced overall quality of v0.5 be improved by combining its
training-only taxonomy sampling and ordinary SFT objective with the useful
late-diagnosis emphasis observed in v0.6? The intended gain is joint quality
across correctness, taxonomy, and first-error localization while preserving
structured-output validity—not improvement in diagnosis alone.

This experiment implements that synthesis as a separately checkpointed
two-stage strategy: ordinary v0.5 supervision first, followed by a moderated
version of v0.6's late diagnostic weighting. It is not a static
moderate-weighting experiment and does not change the training examples,
prompt, base model, decoding, or validation split.

## Synthesis rationale

v0.5 is the foundation because its moderated taxonomy-balanced training set
gave the strongest eligible balance of the completed Qwen runs. v0.6 supplies
the second ingredient: its late diagnostic phase improved correctness and
first-error localization enough to raise balanced utility from `0.4936` to
`0.5137`, but its 4× schedule produced only 46/48 valid outputs and reduced
taxonomy macro F1 to 24.5%.

v0.7 therefore retains v0.5's data, prompt, ordinary objective, and all other
controls for Stage 1, then borrows v0.6's idea of a diagnosis-focused second
stage at a moderated 2× weight. It deliberately omits v0.6's early 4×
correctness phase and its late 4× diagnostic weight. The hypothesis is that
this combination can retain v0.5's eligibility and taxonomy strength while
capturing enough of v0.6's localization gain to improve overall balanced
utility.

## Frozen inputs and controls

Use only the frozen, training-derived
`data/training/v0.5-sft-train.jsonl`, whose generator reads only
`data/processed/train.jsonl`. Verify its metadata and frozen SHA-256
`ea78f215770cf29880532e19126a9c27a28308bb1403c52152c7c995c1139826`
before training. Validation and test records must not be used to construct,
filter, weight, order, or select training examples.

Hold the following v0.5 settings fixed:

- `Qwen/Qwen2.5-3B-Instruct` at revision
  `aa8e72537993ba99e69dfaafa59ed015b17504d1`.
- The v0.2 guidance system prompt, model-native chat template, canonical JSON
  targets, and assistant-only supervised loss.
- Seed `20261004`; NF4/FP16 QLoRA; rank 8; alpha 16; dropout 0.05; learning
  rate 0.0002; 3 total warmup steps; effective batch size 8; maximum sequence
  length 2048; and exactly 60 optimizer steps in total.
- The fixed 48-record validation split and the v0.5 inference protocol:
  greedy decoding, 256 maximum new tokens, one output per example, no retries,
  and no output repair.

Run a matching untouched-base control on the fixed validation split, followed
by exactly one validation run of the final Stage 2 adapter. Use the same prompt,
chat template, quantization, and decoding for both. Do not validate the Stage 1
checkpoint. Training-only smoke checks may verify tokenization, truncation,
field masks, checkpoint loading, and adapter attachment before validation.

The held-out test split must not be read, tokenized, inspected, or used for
debugging or tuning at any point in this experiment.

## Treatment

Train one adapter through two consecutive, separately saved stages. Preserve
the optimizer-step numbering and total 60-step budget across the boundary.

1. **Stage 1: frozen v0.5 recipe, steps 1–30.** Train for 30 optimizer steps
   with ordinary assistant-only SFT loss. Every assistant token in the full
   canonical JSON target has weight 1×. Save the adapter and the training state
   needed to establish an auditable Stage 1 checkpoint.
2. **Stage 2: moderate diagnosis continuation, steps 31–60.** Load and continue
   directly from the saved Stage 1 adapter for 30 additional optimizer steps.
   Continue supervising the full canonical JSON response. Give the complete
   `first_error_step` and `error_taxonomy` fields 2× loss weight, including
   their keys and values. Give `overall_correctness` and every other assistant
   JSON token 1× weight. Save Stage 2 as a distinct final adapter checkpoint.

There is no model reinitialization or fresh adapter between stages. The Stage 2
checkpoint must record its Stage 1 parent and both checkpoint hashes. Document
whether optimizer and scheduler state are resumed; the learning-rate schedule
must implement the same precommitted 60-step run and must not restart or add a
second warmup at the boundary.

This is the operational combination of v0.5 and v0.6: v0.5 supplies the
training set and ordinary first-stage objective, while v0.6 supplies the
late-stage diagnostic-emphasis concept. It differs from v0.6 in both sequencing
and strength. v0.6 applied 4× correctness weighting during steps 1–30 and 4×
diagnostic weighting during steps 31–60. v0.7 instead makes Stage 1 the
ordinary frozen v0.5 objective, saves it separately, and uses only 2×
diagnostic weighting in the continuation.

## Precommitted eligibility and selection rule

The v0.5 anchor is 47/48 valid outputs, 30/48 correctness matches over all
validation records, taxonomy macro F1 `0.3201` (32.0%) over valid outputs,
first-error exact match 15/28 (53.6%) over eligible valid outputs, and balanced
utility `0.4936`:

```
utility = (correctness_accuracy_all_48
           + taxonomy_macro_f1_valid_only
           + first_error_exact_match_valid_only) / 3
```

Balanced utility is the primary overall-quality endpoint, subject to component
floors that prevent a utility gain from hiding regression in validity,
correctness, taxonomy, or localization. The final v0.7 adapter is eligible to
replace v0.5 only if it satisfies every one of these criteria:

1. At least 47/48 outputs are schema-valid.
2. Correctness over all 48 records is at least 30/48 (62.5%).
3. Taxonomy macro F1 over valid outputs is at least `0.3201`.
4. First-error exact match over eligible valid outputs is at least 53.6%.
5. Its balanced utility is strictly greater than v0.5's `0.4936`, using the
   unrounded metric components in the calculation.

Report every component even if an earlier criterion fails. If any criterion
fails, retain v0.5 as the frozen Qwen recipe for cross-family comparison. If
all criteria pass, report v0.7 as an eligible Qwen replacement, but do not use
the held-out test split without a separately committed final-test plan.

## Interpretation boundaries

This single run tests only the specified v0.5-plus-v0.6 synthesis. Static
moderate loss weighting, a hard-example curriculum, contrast-example training
expansion, and auxiliary rationale targets remain untested. The v0.4 and v0.5
experiments changed taxonomy sampling, not curriculum order; v0.6 tested staged
4× field weighting, not this ordinary-SFT-to-2×-diagnosis continuation.

Because validation contains only 48 records and several taxonomy labels have
support one, interpret small differences cautiously. Do not choose thresholds,
examples, reruns, or follow-up changes after examining v0.7 validation results.
